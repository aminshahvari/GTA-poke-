## Area 4 — Gameplay proposals (Show Cards, hand-to-hand delay, Rabbit Hunt): NOT DELIVERED — no code or proposal commit exists on the bridge
Muse searched all refs: no implementation, branch or proposal document for these three items exists yet (the WSOP/TDA rules checklist on file is background research, not a proposal). Audit position, ready for when Claude files them:
- **Show Cards** (voluntary reveal): acceptable only if strictly opt-in by the card holder, never reveals another player's cards, and never while a hand is live with decisions remaining (a shown fold leaks dead-card information to players still acting). Post-hand or all-in-only reveal is the safe rule. It must ride the existing `shown` mechanism in the public snapshot, not a new channel.
- **Hand-to-hand delay:** the engine already implements hand-for-hand synchronization (`hfhState`) for bubble play — a *pace* delay between hands is a different feature. Any inter-hand delay must be server-driven, identical for all tables in hand-for-hand mode, and must not interact with the action clock or level timer (levels advance on the tournament clock, not hand count).
- **Rabbit Hunt** (dealing out the would-be board after a hand ends): integrity hinges on the fairness seal — the revealed cards must be the next cards of the *committed* deck (`server/fair.js` seal), sliced after the hand fully ends, never re-drawn or re-shuffled; if the implementation re-runs the RNG it breaks provable fairness and is a FAIL. Cosmetic only; must be off by default in tournament play or clearly house-ruled.
No verdict can be issued until an exact SHA exists.
